# ตัดต่อสไตล์ช่วยด้วยจ้า

เลือกวิธีนำเสนอจากหน้าที่ของคำพูด: คำถาม → เหตุผล → ตัวอย่าง → ข้อสรุป ใช้ภาพ ข้อความ โมชั่น และเสียงร่วมกันเพื่อสื่อใจความ ไม่ใช้ความถี่ลูกเล่นแทนการเล่าเรื่อง

นี่คือ skill สำหรับเอเจนต์ มีคลังสไตล์ที่วิเคราะห์จากโครงสร้าง CapCut และขั้นตอนนำไปใช้ ไม่ใช่โมเดลที่ฝึกแล้วหรือฟังก์ชันที่แอปเรียกเอง แอปใช้กฎฉบับคัดเลือกที่มีเวอร์ชันใน `app/ks/editing_skill.py` ไม่อ่านหรือรันไฟล์ skill ส่วนตัวอัตโนมัติ

## เลือกและวางงาน

อ่าน [คลังสไตล์อ้างอิง](references/style-library.md) เมื่อต้องเลือกแนวหรือเลียนแบบตัวอย่าง ใช้ brief และตัวเลือกของผู้ใช้เป็นหลัก หากไม่ได้ระบุแนว ให้เลือกตระกูลที่ตรงเนื้อหาแล้วแจ้งสั้น ๆ โดยทำส่วนที่ทำได้ต่อ

- Econ: ปัญหา → เชื่อมความรู้ → กระบวนการ/การประยุกต์ → payoff
- Ai นิติ: ความน่าเชื่อถือ → วิธีทำงานของระบบ → หลักฐาน/ความรับผิดชอบ
- การตลาด: ข้อสงสัย → แย้งด้วยเหตุผล → แยกแนวคิด → บทสรุป

อ่านซับ CapCut ที่มีเวลาและดู/ฟังช่วงที่เกี่ยวข้องก่อนตัดสินจังหวะจริง จัดเรื่องให้เข้าใจได้ด้วยตัวเอง ระบุว่าช่วงใดเป็น hook, คำตอบ, หลักฐาน และ payoff; ตรวจซับก่อน/หลังขอบตัดและรายการที่เกริ่นไว้ให้ครบ

ทำ beat sheet ขนาดพอดีงาน: เวลา/แหล่งคำพูด, หน้าที่ของช่วง, ซับจริง, ข้อความออกแบบ, ภาพ, โมชั่น, เสียง, เหตุผล, หลักฐานหรือสิ่งที่ต้องตรวจ เวลาในตัวอย่างอ้างอิงไม่ใช่เวลาที่ต้องคัดลอกไปงานใหม่

## จัดภาพ ซูม ครอป และตำแหน่งคำ

อ่าน [Brand Storm EP.11 — จัดภาพก่อนจัดคำ](references/brand-storm-ep11.md) เมื่อต้องออกแบบผู้พูดร่วมกับ Super Text หรือเรียนรู้การซูม/ครอป/สลับกล้อง ทำ scene card ให้ครบ: กล้อง/เสียงที่เลือก, crop ฐาน, กรอบผู้พูด, พื้นที่ว่าง, anchor ของกลุ่มคำ, บทบาทคำ, ชนิดการตัด/การเคลื่อน, เวลาและหลักฐาน, สิ่งที่ยังต้องตรวจภาพ/เสียง รักษาตำแหน่งเป็นตระกูลตลอดความคิด ไม่สุ่มวางรายซับ การเลือก safe area อย่างเดียวไม่ยืนยันว่าหลบใบหน้า

แยก crop ฐาน, static punch-in, animated zoom, camera cut และ source jump ก่อนวางจังหวะ เลือกเหตุผลจากคำพูดและองค์ประกอบงานใหม่ ไม่ยกค่าซูมหรือความถี่จาก reference เป็นสูตร ตรวจต้น–กลาง–ท้ายการเคลื่อนและรอยต่อจริง อนุญาตให้คงช็อตและไม่มี Super Text เพื่อพักสายตา

## ทำให้เป็นภาพและเสียง

แยกซับคำพูดออกจากข้อความออกแบบ ซับรักษาคำพูดจริง; ข้อความเน้นย่อหรือจัดวลีได้เมื่อความหมายยังตรงและตรวจย้อนกลับถึงคำพูดได้ เลือกหนึ่งความสัมพันธ์ที่ต้องสื่อในแต่ละ beat เช่น คำถาม/คำตอบ, สิ่งที่เปลี่ยน/สิ่งที่คงเดิม, A→B→C หรือรายการที่ค่อย ๆ เปิดตามเสียง

ใช้การตั้งค่าฟอนต์ สี และ safe area ของงานปัจจุบันก่อน ทุก reference พบตระกูล DB Heavent แต่น้ำหนักต่างกัน อย่าเหมารวมทุกงานเป็น Blk เดียว เลือก SFX ตามหน้าที่ เช่น typing สำหรับการก่อตัว, UI สำหรับขั้นตอน, impact สำหรับข้อสรุป พร้อมตรวจการฟังจริง

เมื่อแก้ draft หรือนำผลกลับ CapCut อ่าน [เส้นทางทำงานและการตรวจผล](references/capcut-workflow.md) ก่อนลงมือ

## ออกแบบคำให้สัมพันธ์กับเรื่อง

เลือกแบบจากคำพูด ไม่วนแบบสุ่มเพื่อให้ดูมีลูกเล่น:

- คำหลัก–คำรอง: แยกวลีที่มีความหมาย เน้นเพียงจุดเดียว ไม่ตัดกลางคำเพื่อให้ยาวพอกัน
- สองบรรทัดเท่ากัน: วัดความกว้างจากฟอนต์จริง เช่น “เพื่อทำ” ด้านบนและ “ภารกิจให้สำเร็จ” ด้านล่าง ปรับขนาดตัวอักษร ไม่ยืดรูปตัวอักษร
- คำขยี้: ใช้วลีสั้นขนาดใหญ่เป็นจุดพักหรือข้อสรุป ไม่ทำทุกคำเป็น hero
- คำถาม: จัดคำถามให้อ่านเป็นประโยค ไม่เผยคำตอบก่อนเสียงเฉลย ถ้าไม่มีเวลาขอบคำ ให้เลือกคำถามอย่างเดียวหรือแสดงประโยคเต็มตามซับ โดยไม่อ้างว่าเฉลยตรงเสียง อย่าสร้างจังหวะถาม–เฉลยปลอม
- คู่เปรียบเทียบ: วางสองฝั่งหรือเยื้องบรรทัด แยกสีรองกับคำหลักให้เห็นความสัมพันธ์ เช่น สิ่งที่เปลี่ยน/สิ่งที่ยังใช้ได้
- รายการ: คงจำนวนและลำดับจากคำพูด ห้ามเติมเลขรายการที่ผู้พูดไม่ได้พูด ใช้ระยะห่างจัดกลุ่มแทน สูงสุดสามบรรทัดที่อ่านได้ การค่อย ๆ เพิ่มต้องมีเวลาคำ/ขอบซับจริง ถ้ามีเพียงเวลาทั้งท่อน ให้แสดงรายการพร้อมกันและบอกข้อจำกัด

ในแอปโหมดทั้งคลิปเป็นกฎในเครื่องที่เสนอแบบเริ่มต้น ผู้ใช้ปรับรายประโยคได้: เลือกวลีจากคำพูดเดิม แบ่งบรรทัด เลือกคำเน้น แบบ โมชั่น หรือซ่อนชุดนั้น บันทึกก่อนตรวจพรีวิวและสร้างสำเนา ห้ามแก้เวลาแฝงผ่านช่องข้อความ ซับคำพูดยังอยู่ครบแม้ซ่อน Super Text ช่วงธรรมดาเลือกไม่เน้นได้ ไม่จำเป็นต้องมี hero ทุกช่วง หากยังมีการแก้ค้าง ต้องบันทึกหรือคืนค่าก่อนสร้าง และผลที่เตรียมต้องใช้ revision เดียวกับพรีวิวที่ตรวจ

พรีวิวต้องเล่น/หยุด/เลื่อนได้ตลอดช่วง มีภาพกล้องและเสียงต้นฉบับ พร้อมซับกับข้อความออกแบบให้เห็นร่วมกัน การแก้แบบต้องรักษาภาพที่โหลดและตำแหน่งเวลา ใช้ตำแหน่ง/ขนาด/สี/จุดโมชั่นเดียวกับ native output และแยกให้ชัดว่าพรีวิวเว็บยังจำลองเส้นขอบและเอฟเฟกต์ภาพบางชนิด ตรวจ CapCut จริงก่อนรับรองคุณภาพ

## ตรวจ ส่งมอบ และเรียนรู้

ตรวจภาพ/เสียงช่วงที่เปลี่ยนใน CapCut โดยเฉพาะรอยต่อ การอ่านภาษาไทย การทับใบหน้า จังหวะเสียงและสื่อหาย หากทำได้เพียงตรวจ JSON ให้รายงานตามนั้น ส่งผลสำเนา/preview พร้อมจุดที่ต้องตรวจและทางกู้คืนตามเส้นทางเดิม

เก็บ feedback เป็นกรณีเฉพาะ: เวลา, สิ่งที่ผู้ใช้แก้, เหตุผล และบริบท ทดสอบกับคลิปใหม่ก่อนยกระดับเป็นกฎร่วม ความเหมือนคนตัดต้องประเมินจากผลดู/ฟังและการยอมรับของผู้ใช้ ไม่ให้เปอร์เซ็นต์จากจำนวนแทร็ก
