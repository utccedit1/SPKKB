# P0.12 ตรวจซ้ำ 1.5.57 — 30 ตุลาคม 2026

ตรวจซอร์ส B-roll, การนำเข้าผล, receipt และหลักฐาน readiness เดิม โดยใช้โปรเจกต์และข้อมูลจำลอง ไม่เขียนโปรเจกต์ผู้ใช้ ไม่ใช้ AI/Artlist จริง และไม่เปลี่ยนซอร์สหรือ release

## พบข้อผิดพลาด

1. **P1: การเขียนโปรเจกต์สำเร็จแต่บันทึก receipt ล้มเหลวทำให้แจ้งเป็น error และรายการผลยังรอนำเข้า** — `app/ks/cli_lab_commit.py:235-242` เขียน mirror transaction แล้วเรียก `cli_results.imported` นอก transaction; หาก receipt ล้มเหลว เช่นพื้นที่เต็ม คำสั่งส่ง exception หลังโปรเจกต์เปลี่ยนแล้ว Fixture `receipt_probe.py` จำลองข้อผิดพลาดการเขียน receipt โดยผลจริงคือ commit raised, fixture project changed, result still pending; สำเนาสำรองยังมีตามกระบวนการเดิม ไม่ได้ยืนยันความถี่บนเครื่องจริง ควรเพิ่มสถานะ commit ที่กู้คืนได้และตรวจผลก่อนเสนอให้ลองใหม่ ทั้งเส้นทางนำเข้าที่ใช้โค้ดร่วม
2. **P1: สถานะนำเข้า B-roll หลัง timeout ไม่ชัดเจน** — `app/ks/broll_auto_ui.py:27,44` รอทุก POST สูงสุด 30 วินาทีรวมการคัดลอกและนำเข้า เมื่อ fetch ถูกยกเลิก UI ซ่อนปุ่มและบอกให้ตรวจผลใหม่ แต่การหยุดรอของ client ไม่รับประกันว่าฝั่งเซิร์ฟเวอร์หยุดเขียน `timeout_ui_probe.js` จำลองการหมดเวลาและเซิร์ฟเวอร์ทำเสร็จภายหลังเพื่อยืนยันข้อความ/UI; ไม่ได้จำลองการหน่วงดิสก์จริง ควรมีสถานะงานนำเข้าและกู้ผลได้แม้ขาดการเชื่อมต่อ โดยไม่ส่ง POST ซ้ำอัตโนมัติ
